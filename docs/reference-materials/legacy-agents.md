# AGENTS.md

## 项目说明

本项目用于建设西部智车（重庆）科技有限公司官网。

网站首版的主要任务是：清晰介绍公司，重点展示产品与解决方案、真实案例，并承接商务咨询；同时保留后续增加产品、案例、新闻、下载中心和英文站的能力。

## 开始工作前

1. 先阅读本文件，再阅读 `docs/` 中的最新版信息架构与内容视觉规范。
2. 查看资产映射表和 `assets/` 中的实际文件，再决定页面使用哪些素材。
3. 如果项目已有代码，先识别框架、包管理器、目录结构和现有脚本，不要擅自重建项目或替换技术栈。
4. 若资料之间存在冲突，以版本号较新的文件为准；仍无法判断时，列出冲突并询问用户。

## 资料优先级

按以下顺序理解项目：

1. 本文件：长期约束与不可违反的项目规则。
2. `docs/01_官网信息架构*.md`：页面、导航、路由与内容关系。
3. `docs/02_官网内容与视觉设计规范*.md`：页面文案、视觉、排版与交互。
4. `docs/02_官网内容资产映射表*.xlsx`：素材与页面位置的对应关系。
5. `assets/`：网站实际使用的 Logo、图片、视频和资料。
6. `references/`：视觉方向参考，不要求像素级照抄。

旧 PDF、旧压缩包和历史稿只可用于追溯，不得覆盖已整理的新版资料。

`首页 / 产品与解决方案 / 案例 / 关于我们 / 联系我们`

`认识公司 → 找到产品或方案 → 查看案例验证 → 提交需求`

## 开发原则

- 延续项目现有技术栈和包管理器；新增生产依赖前说明必要性。
- 产品、案例、导航和标签必须使用结构化数据驱动，不要把重复内容散落硬编码在页面组件中。
- 产品详情与案例详情使用可复用模板，并为每项内容建立稳定、可读的 slug。
- 优先建立统一的颜色、字体、间距、断点和组件变量，避免页面内出现大量魔法数。
- 复用公共组件：导航、页脚、行动区、产品卡片、案例卡片、筛选标签和详情模块。
- 图片与视频从项目资产目录引用；处理大小写、中文文件名、空格和相对路径兼容问题。
- 对大图和视频进行合理压缩、懒加载和响应式处理，避免牺牲首屏性能。
- 不提交密钥、口令、个人隐私、构建缓存或与项目无关的大文件。
- 未经用户明确要求，不执行部署、域名配置、外部发布或不可逆操作。

## 工作方式

- 开始较大改动前，先简要说明理解、计划和可能影响的页面。
- 优先完成可运行的 MVP，再逐步补齐动效和精细视觉。
- 若一个问题可以从现有资料和代码确定，直接处理；只有会实质改变业务口径、视觉方向或技术方案时才询问用户。
- 保留用户已有改动，不覆盖与当前任务无关的文件。
- 修改页面结构、内容模型或关键口径时，同步更新相关文档。

## 验证要求

每次实现后，根据项目实际脚本运行适用的检查：

- 构建
- 类型检查
- Lint
- 测试

同时人工检查：

- 五个一级页面和已发布详情页可正常访问。
- 导航、按钮、筛选、表单入口和返回路径可用。
- 图片、Logo、视频和字体无丢失路径。
- 桌面端与移动端无明显溢出、遮挡和错位。
- 页面无浏览器控制台错误。
- 页面没有旧“数据底座”口径、虚构内容或内部审核文字。

如果某项检查因项目尚未提供脚本或内容而无法执行，需要在交付说明中明确写出，不得假称已经通过。

## 完成标准

只有同时满足以下条件，任务才算完成：

1. 实现符合最新信息架构和视觉规范。
2. 内容与素材来源可追溯，没有虚构信息。
3. 主要页面与交互在桌面端和移动端可用。
4. 适用的构建与代码检查通过。
5. 已说明仍待确认的业务内容、素材授权和技术限制。
